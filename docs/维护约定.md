# 学习项目维护约定

## 内容放在哪里

- 模型解析、原文、图件、答疑与阅读进度继续维护在 `learning/模型详解/`，保留已有分类和编号，避免破坏大量互链。
- 专题精读、综述和学习方法放在 `learning/`；小型实现练习放在 `learning/exercises/`。
- 项目使用说明放在 `docs/`，可复用笔记模板放在 `templates/`。
- 原课题的文稿、演示稿、制度文件、实验队列和工具备份放在 `archive/road-debris-detection/`。归档目录不作为当前学习任务或工具配置的入口。

## 命名与链接

长期目录按用途或主题命名，不使用整理日期或 `cleanup` 命名。日期用于迁移记录、阶段记录和有时间含义的历史版本。已有论文编号与图件编号保留，不为了表面统一而批量改名。

新增笔记使用清晰的模型或论文名称，优先扩展现有主题；跨文件引用使用相对链接，避免写入某台机器的绝对路径。新增 PDF 或图件后，同时更新对应笔记和论文清单。

## 一篇笔记的完成标准

从 [论文笔记模板](../templates/paper-note.md) 开始，至少写清来源、问题、输入输出、方法流程、关键证据和未解决的问题。严格区分论文报告、代码实现和自己的推断；没有运行过的实验标注“未复现”。

代码映射应标明仓库、版本或提交以及文件位置。外部项目的文件不要写成貌似存在于本仓库的路径。阅读进度更新到[现有进度表](../learning/模型详解/阅读进度.md)，跨模型问题更新到[答疑目录](../learning/模型详解/答疑记录.md)，避免再建一套重复状态表。

## 修改后检查

1. 从根目录 README 能找到新增内容；相对链接、图片和 PDF 能打开。
2. 练习入口保持 `python learning/check_progress.py` 可用；未实现的练习不应被误报为已完成。
3. 用 `git diff` 检查改动；不要将运行缓存、临时输出或机器凭据加入版本控制。

Obsidian 同步独立于本地项目维护：仅在明确要求记录到 Obsidian 时使用相应技能，先展示完整草稿与目标位置，收到“保存并同步”后才写入。
