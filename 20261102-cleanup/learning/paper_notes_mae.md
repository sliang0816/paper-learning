> 论文全名：Masked Autoencoders Are Scalable Vision Learners
> 关联模型详解：[03_视觉语言VLM/02_MAE.md](模型详解/03_视觉语言VLM/02_MAE.md)（架构/项目关系已写在那边，本文件专记论文原文的精读细节，尤其是消融实验数据）

---

## 一句话总结

MAE 把图切成 patch、随机盖住 75%，编码器只看剩下 25% 的可见 patch（省算力），轻量解码器再用这些编码结果 + 占位符去重建被盖 patch 的原始像素——全程不用任何标签。对我的研究的意义：我有 ~2TB 无标注路面监控视频，MAE 提供了一条"不用标注也能预训练骨干"的路，可以作为未来工作的加分实验。

## 速览记录

### Abstract 核心信息
- 核心方法：随机遮住图像 patch、重建缺失像素，基于两个核心设计——① 非对称编码器-解码器（编码器只处理可见 patch，不含 mask token）；② 高掩码率（如 75%）。
- 效果：训练加速 3 倍以上，同时提升精度；ViT-Huge 微调后达到 87.8% top-1（当时仅用 ImageNet-1K 数据方法里的最高值）。
- 下游任务（检测、实例分割、语义分割）上迁移效果超过有监督预训练。

### Figure 1 理解
论文的核心架构图：输入图切 patch 后随机遮住一大部分（论文默认画的是 75%），编码器（大、贵）只吃可见的一小撮 patch；编码完之后再把 mask token（可学习的占位向量）补回去、和编码结果拼一起，交给一个小的解码器去重建整张图的像素。预训练结束后解码器直接丢弃，只留编码器去做识别类下游任务。

### 引言里三点"为什么 BERT 的思路不能直接搬进视觉"（原文 Introduction 部分，我自己拆成三条）
1. **架构障碍**：以前 CNN 不好处理"挖掉再补"这种操作（卷积在规则网格上滑动，很难自然地插入 mask token 或位置编码这类"指示符"）；ViT 把图像切成 patch token 之后，这个障碍就消失了。
2. **信息密度不同**：语言是人类高度浓缩过的信号，遮几个词就很难猜；图像是自然信号，空间冗余大得多——遮一小块，靠周围邻居插值就能补出来，学不到真正的语义。MAE 的解法很直接：**遮到很高的比例**（如 75%），把这条"靠插值作弊"的路堵死。
3. **解码器角色不同**：语言里解码器要预测"词"，本身就带丰富语义，所以 BERT 的解码器可以很简单（一个 MLP 就够）；图像里解码器要重建的是像素，语义层级天然更低。论文原文这句话我觉得是全篇最关键的一个洞察："we found that for images, the decoder design plays a key role in determining the semantic level of the learned latent representations"（解码器设计本身，直接决定了编码器学到的表示处在哪个语义层级）——这条洞察后面直接导出了"解码器要有一定深度"这个消融实验的解释。

### Conclusion / 意义
- 把 BERT 式自监督成功搬到了视觉里，证明"简单地重建被遮的原始像素"这条最朴素的路就能训出强表示，不需要像对比学习那样精心设计增强、也不需要像 BEiT 那样搞一个额外的离散 tokenizer。
- 论文特别强调"可扩展"（Scalable）——模型越大、数据越多，收益越明显，这条趋势和 NLP 里自监督预训练的经验一致。

## 精读记录（Section 3 核心方法）

### 3.1 Masking（掩码策略）
按 ViT 的方式把图切成规则的、不重叠的 patch，然后**均匀随机采样**一部分留下、其余全部丢弃（不是"设为0"，是真的从输入序列里拿掉，编码器压根看不到）。论文管这个叫"random sampling"，强调这个策略很朴素——随机、无放回、均匀分布，没有额外花样。

**为什么强调"均匀"**：论文提到均匀分布能避免"中心偏置"（center bias，即被遮的 patch 更集中在图像中央附近），这个我原来没想到，算是个细节但合理的工程考量。

**高掩码率的直接后果**：把大部分冗余信息去掉之后，剩下的任务没法靠"从可见邻居 patch 里推断/延伸纹理和线条"来完成，逼模型去做更接近"整体理解"的推断（论文原文形容为需要 holistic understanding，不是靠低层图像统计量能应付的）。

### 3.2 MAE 编码器
就是标准 ViT，但**只作用于可见、未被遮住的 patch**——被遮的 patch 直接从输入里移除，不参与编码器的任何计算，也不用什么占位符去补。这一点后面在消融实验里（Table 1c）证明极其关键，不只是"图省事"，而是被验证过的、直接影响精度和速度的设计。

### 3.3 MAE 解码器
输入是"编码后的可见 patch + mask token"拼起来的**全量**token 序列（图 1 里画得很清楚）。每个 mask token 是一个**共享的、可学习的向量**，用来标记"这里原本有一个我需要预测的 patch"。因为要保留位置信息（不然 mask token 根本不知道自己对应图里哪个位置），这里会重新给全部 token 加一遍位置编码。解码器本身也是若干层 Transformer block，但**可以做得比编码器窄、比编码器浅**——论文原话大意是解码器每个 token 的计算量能做到编码器的不到 10%。因为解码器只在预训训练阶段存在（下游任务直接扔掉），它的设计可以完全独立于编码器去调，这也是"非对称"这个词的第二层含义（除了输入的 token 数不对称，两边的容量大小也不对称）。

### 3.4 重建目标
用解码器输出去预测每个被遮 patch 的**原始像素值**，损失是像素空间的 MSE，而且**只在被遮的 patch 上算**（可见 patch 不参与损失）——这点和经典去噪自编码器不一样，论文脚注里说清楚了：如果对所有像素都算损失（不管有没有被遮），精度会掉大约 0.5%，所以只在被遮处算损失是"结果驱动"的选择，不是随便定的。

论文还提到一个变体：**每个 patch 内部先做归一化**（用该 patch 内所有像素的均值和标准差去归一化），再拿归一化后的值当重建目标——这样做能提升表示质量（局部对比度被放大了）。

### 3.5 简单实现（我觉得这段挺巧妙，记一下）
整个"随机丢弃 75% patch、留 25% 给编码器、之后再补回去"这个过程，工程上不需要写任何"稀疏运算"的特殊代码：先给每个 patch 生成一个 token（线性投影+位置编码），把这列 token 随机打乱（shuffle），砍掉列表末尾对应掩码比例的那一段，剩下的送编码器；编码完之后，把一堆 mask token 拼回列表末尾，再按打乱前的顺序"还原"（unshuffle）回去，交给解码器处理。因为只是列表操作（打乱/截断/拼接/还原顺序），几乎没有额外开销。

## 实验结果记录（Section 4，ViT-L/16 骨干，ImageNet-1K）

> 以下数字全部来自论文 Table 1 / Table 2 / Figure 5 / Figure 7，是这次精读里我觉得最有价值的部分——之前只看"模型详解"里的概述，不知道每个设计选择背后原来都有这么扎实的消融数据撑着。

### (a) 掩码率（Figure 5）
- **微调(fine-tuning)** 准确率随掩码率(10%→90%)变化：83.2 / 83.4 / 83.4 / 84.7 / 84.9 / **85.0**(70%附近最高) / 84.9 / 84.9 / 84.5 / 83.0（%），**在 40%~80% 这个很宽的范围内都很平坦**。
- **线性探测(linear probing)** 准确率：54.6 / 58.9 / 61.7 / 67.0 / 69.9 / 71.8 / 73.2 / **73.5**(75%时) / 71.8 / 66.1（%），**随掩码率持续爬升，最高最低差了近 20 个百分点**（54.6% vs 73.5%）。
- 论文选 75% 作为默认值。对比 BERT 常用的 15%、以及此前视觉领域相关工作用的 20%~50%，MAE 的掩码率高出一大截，这是论文里最反直觉、也是我印象最深的一条结论。

### (b) 解码器深度（Table 1a）
| 层数 | ft | lin |
|---|---|---|
| 1 | 84.8 | 65.5 |
| 2 | 84.9 | 70.0 |
| 4 | 84.9 | 71.9 |
| **8（默认）** | 84.9 | **73.5** |
| 12 | 84.4 | 73.3 |

微调几乎不受解码器深度影响，但线性探测在 8 层之前持续提升（涨了近 8 个百分点）。论文的解释呼应前面提到的那句关键洞察：解码器不够深，"重建像素"这种低语义层级的计算负担就会被迫压在编码器身上，编码器输出的表示因此不够抽象；解码器够深，才能把这部分"脏活"留在解码器里，让编码器专心输出语义化的表示。

### (c) mask token 放哪里（Table 1c + Table 2）
| 方案 | ft | lin | 训练FLOPs |
|---|---|---|---|
| 编码器里也塞 mask token | 84.2 | 59.6 | 3.3× |
| **只喂可见 25%（默认）** | **84.9** | **73.5** | **1×** |

差距很大：线性探测掉 14 个百分点，算力还多花 3.3 倍。论文解释是"训练-部署不一致"——如果编码器训练时见惯了大量 mask token 占位符，但下游真实图像是完整的、没有这种占位符，两种输入分布不一样，会拖累精度。Table 2 给出具体墙钟时间：默认设置下 ViT-L 从 42.4 小时降到 15.4 小时（2.8 倍提速），换成 1 层解码器或 ViT-H 骨干时提速能到 3.5~4.1 倍。

### (d) 重建目标（Table 1d）
| 目标 | ft | lin |
|---|---|---|
| 像素（无归一化，早期默认对照） | 84.9 | 73.5 |
| **像素（每patch归一化，效果最好）** | **85.4** | **73.9** |
| PCA（96个主成分） | 84.6 | 72.3 |
| dVAE 离散 token（BEiT式） | 85.3 | 71.6 |

归一化像素效果最好；dVAE 微调略有优势但线性探测更差，而且需要额外训练一个 tokenizer（依赖 2.5 亿张图、且这个 tokenizer 本身是个不小的卷积网络，多耗约 40% 算力）——论文的结论是直接用像素不用背这些包袱，这也是"Simple"这个词在标题里的来源。

### (e) 数据增强（Table 1e）
| 增强方式 | ft | lin |
|---|---|---|
| 无增强(仅center-crop) | 84.0 | 65.7 |
| 固定尺寸裁剪 | 84.7 | 73.1 |
| **随机尺寸裁剪（默认）** | **84.9** | **73.5** |
| 裁剪+色彩抖动 | 84.3 | 71.9（反而下降） |

MAE 几乎不需要数据增强，这一点论文特意拿来对比对比学习方法（MoCo/DINO 这类）——那条路线严重依赖精心设计的数据增强去构造"同一张图的不同视角"，MAE 不需要，因为"重建被抠掉的一大片区域"这件事本身就是个足够难、足够丰富的任务了。

### (f) 掩码采样策略（Table 1f）
| 策略 | ft | lin |
|---|---|---|
| **random 75%（默认）** | **84.9** | **73.5** |
| block 50% | 83.9 | 72.3 |
| block 75% | 82.8 | 63.9（明显更差） |
| grid 75% | 84.0 | 66.0 |

随机均匀采样最好；分块式在高掩码率下反而更差——大片连续区域被整块抠掉后完全没有局部线索，任务要么无解要么模型走捷径，两种情况都伤害表示质量。

### (g) 整体收益对比
ViT-L 三组数字对比：从零训练（原版超参）76.5% → 从零训练（强正则配方）82.5% → **MAE 预训练 + 仅 50 epoch 微调 84.9%**（对比从零训练要 200 epoch）。仅用四分之一的微调步数就反超将近 2.5 个百分点，说明微调精度很大程度上是"吃预训练的老本"。最终 ViT-Huge 达到 87.8%。

### Figure 7（训练时长）
预训练 epoch 数从 100 加到 1600，微调准确率从 82.3% 涨到 85.1%，线性探测从 57.3% 涨到 75.1%——训练更久还在稳定涨，还没饱和。默认用的是 800 epoch。

## 与我的研究的关系

- **直接可用的思路**：本项目自采了约 2TB 无标注路面监控视频（目前标注的只有训练 3679 / 验证 735 张），MAE 提供了一条"拿这些无标注视频帧去预训练骨干、再用现有标注微调"的路，尤其可能对标注稀缺的 GL/ME 这类类别有帮助（自监督表示部分弥补标注不足）。
- **可以直接照搬的超参**：读完消融实验后，如果真做这个实验，**掩码率直接用论文验证过的 75%**，不需要自己重新扫一遍；**数据增强用简单的随机裁剪就够**，不需要为路面场景设计复杂的增强流程——这两条论文已经用扎实的消融证明过。
- **需要注意的不匹配**：MAE 预训练的是 **ViT** 骨干，本项目主检测器是 CNN 式的 YOLOv8——如果真要接上，得换成 ViT 骨干，或者改用 MAE 思想的卷积变体（如 SparK、ConvNeXt-V2），不能直接嫁接。
- **优先级**：这属于开题后可选的"增强实验"，不进当前主线（EXP-001~004），算力和时间允许时可以跑一版"MAE 预训练骨干 vs ImageNet 预训练骨干"的对比作为加分项。

## 架构精读补充（数字规格，供实现时对照）

- **patch 大小**：跟随 ViT 的切法，规则、不重叠的 patch（常见配置是 16×16）。
- **编码器**：标准 ViT，主实验用 ViT-Large/16 做消融，最终最强结果用 ViT-Huge。
- **解码器**：默认深度 8 层、宽度 512 维，每 token 计算量约为编码器（ViT-L，24层/1024维）的不到 10%。
- **训练细节**：默认预训练 800 epoch；损失只在被遮 patch 上算 MSE；微调阶段 ViT-L 只需要 50 epoch（远少于从零训练的 200 epoch）。

## 读完后还不完全确定的地方

1. 归一化像素重建目标里，"每个 patch 内部算均值方差再归一化"具体是每个 patch 独立算，还是有别的统计口径？—— 论文原文说是"the mean and standard deviation of all pixels in a patch"，确认是**每个 patch 各自独立统计**，不跨 patch。
2. dVAE tokenizer 需要额外 2.5 亿张图预训练——这个规模对我而言完全不可复现，如果要对比 BEiT 式的方案，只能用别人训好的公开 tokenizer，不能自己复现这一步。
3. 论文的下游检测/分割实验（用 ViTDet 之类的框架）细节还没细看，因为本项目主检测器是 YOLOv8（CNN），这部分对本项目参考价值有限，暂不深入。
