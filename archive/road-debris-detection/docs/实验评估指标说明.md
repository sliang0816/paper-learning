# 实验评估指标说明

本文档统一解释 `experiments/run_experiment.py` 输出的检测指标。论文、实验记录和答辩材料均采用本文件口径。

## 1. 评估数据口径

- `val_*`：训练过程使用的验证集指标，用于观察收敛和选择模型。
- `test_*`：独立测试集指标，用于最终实验对比和论文报告。
- 正式数据配置为 `independent_stratified_6class.yaml`。
- 测试集不得参与模型训练、超参数选择、阈值调优和早停。
- 四个模型变体必须使用相同的数据、输入尺寸、训练轮数、随机种子和评估流程。

## 2. IoU

交并比（Intersection over Union，IoU）衡量预测框与真实框的重叠程度：

```text
IoU = 预测框与真实框的交集面积 / 预测框与真实框的并集面积
```

IoU 越接近 1，预测框定位越准确。`IoU=0.5` 表示交并比达到 0.5 时可按匹配规则判为正确检测。

## 3. Precision 与 Recall

精确率：

```text
Precision = TP / (TP + FP)
```

表示模型给出的检测框中有多少是真目标。Precision 低通常说明误检较多。

召回率：

```text
Recall = TP / (TP + FN)
```

表示真实目标中有多少被模型检出。Recall 低通常说明漏检较多。

其中：

- TP：正确检出的目标；
- FP：错误检测框；
- FN：未被检出的真实目标。

## 4. AP 与 mAP

AP（Average Precision）是某一类别在不同置信度阈值下 Precision–Recall 曲线的面积。它综合评价该类别的误检和漏检情况。

mAP（mean Average Precision）是所有参与检测类别 AP 的平均值：

```text
mAP = (AP_PL + AP_ME + AP_ST + AP_VP + AP_TD + AP_OT) / 6
```

本项目六类检测类别为：

| 缩写 | 中文 |
|---|---|
| PL | 塑料 |
| ME | 金属 |
| ST | 沙石 |
| VP | 车辆零件 |
| TD | 交通设施 |
| OT | 其他 |

GL（玻璃）和 RU（橡胶）不参与 YOLOv8s 训练，主要用于 CLIP 零样本评估，因此不计入六类检测 mAP。

### mAP@0.5

以 `IoU ≥ 0.5` 作为正确匹配条件计算各类 AP，再求平均。该指标相对宽松，主要反映模型能否发现目标。

脚本字段：

```text
val_mAP50
test_mAP50
```

论文主表应优先报告独立测试集的 `test_mAP50`。

### mAP@0.5:0.95

分别在 IoU 阈值 0.50、0.55、……、0.95 下计算 AP，再对全部阈值和类别求平均。该指标比 mAP@0.5 更严格，同时考察检测能力和边界框定位精度。

脚本字段：

```text
val_mAP50_95
test_mAP50_95
```

如果 mAP@0.5 较高但 mAP@0.5:0.95 较低，通常说明目标能够被发现，但边界框定位不够精确。

### per_class_AP50

各类别在 IoU=0.5 下的 AP。总体 mAP 可能掩盖少数类的性能，因此论文中应同时报告：

```text
PL / ME / ST / VP / TD / OT 的 AP@0.5
```

特别关注 ST、VP、TD 等样本较少或小目标特征明显的类别，判断 P2 和 CBAM 是否真正有效。

## 5. 模型效率指标

### params_M

模型参数量，单位为百万（M）。用于衡量模型复杂度。

### latency_ms

`batch=1` 时单张图像的模型推理时间，单位毫秒。当前取 Ultralytics 返回的 inference 时间，不等同于完整业务系统端到端延迟。

### fps

根据推理延迟换算：

```text
FPS = 1000 / latency_ms
```

FPS 越高，模型实时性越好。不同硬件、CUDA、精度模式和输入尺寸下的 FPS 不可直接横向比较。

### train_hours

本次训练耗时，单位小时，仅用于记录实验资源消耗。

### 复现字段

`metrics.json` 还会保存实际完成轮数、batch、输入尺寸、patience、workers、AMP、
随机种子、数据 YAML/划分清单/预训练权重/最佳权重的 SHA-256、Git 提交和软件
环境。正式比较前先核对这些字段；名称相同但数据摘要不同的运行不能直接并表。
测试评估会显式重新加载落盘的 `best.pt`，不会把最后一轮内存权重误当最佳权重。

## 6. 实验结果的主要比较

| 对比 | 解释 |
|---|---|
| `p2_cbam` vs `baseline` | P2+CBAM 联合改进是否有效 |
| `p2_only` vs `baseline` | P2 的独立贡献 |
| `cbam_only` vs `baseline` | CBAM 的独立贡献 |
| `p2_cbam` vs 两个单模块 | P2 与 CBAM 是否互补 |

不能只比较 mAP@0.5。正式结论至少同时考虑：

- `test_mAP50`；
- `test_mAP50_95`；
- Precision、Recall；
- 各类别 AP50；
- 参数量、延迟和 FPS。

## 7. CLIP 指标与检测 mAP 的区别

CLIP 模块主要报告 GL/RU 零样本 top-1、OOD AUC、检测召回率和端到端识别率。这些指标不能与 YOLO 的 mAP 混写：

- YOLO mAP：评价已知六类的目标检测；
- CLIP top-1：评价目标裁剪区域的语义分类；
- OOD AUC：评价已知类与预留零样本类的区分能力；
- 端到端识别率：同时受到检测漏检和 CLIP 分类错误影响。

### OOD AUC

OOD（Out-of-Distribution）表示分布外样本。本项目将类别划分为：

- 已知类：PL、ME、ST、VP、TD、OT；
- 预留零样本/OOD 类：GL、RU。

对每个目标图像块，CLIP 分别计算它与六个已知类文本的余弦相似度，并取最大值：

```text
known_max_sim = max(sim_PL, sim_ME, sim_ST, sim_VP, sim_TD, sim_OT)
```

已知类通常与至少一个已知类文本具有较高相似度；GL/RU 与六个已知类文本的最大相似度理论上较低。脚本因此使用：

```text
OOD score = -known_max_sim
```

分数方向为：

- OOD score 越高，越可能是 GL/RU；
- OOD score 越低，越可能属于六个已知类。

将 GL/RU 标记为正类（1），六个已知类标记为负类（0），不断改变 OOD 判定阈值，可以得到 ROC 曲线：

- TPR：被正确识别为 OOD 的 GL/RU 比例；
- FPR：被错误识别为 OOD 的已知类比例。

ROC 曲线下面积就是 OOD AUC。它也可以理解为：随机选取一个 OOD 样本和一个已知类样本，模型给 OOD 样本更高 OOD 分数的概率。

| OOD AUC | 解释 |
|---:|---|
| 0.50 | 接近随机区分 |
| 0.60～0.70 | 区分能力较弱 |
| 0.70～0.80 | 有一定区分能力 |
| 0.80～0.90 | 区分能力较好 |
| 0.90～1.00 | 区分能力很强 |
| 1.00 | 完全区分 |
| < 0.50 | 分数方向可能相反或方法失效 |

例如，OOD AUC=0.85 表示随机选择一个 GL/RU 目标和一个已知类目标时，模型约有 85% 的概率给 GL/RU 更高的 OOD 分数。

计算 OOD 分数时只能使用六个已知类文本，不能把 GL/RU 文本加入 `known_max_sim`，否则会把预留类别名称泄漏到“已知度”计算中。

零样本 top-1 与 OOD AUC 的任务不同：

| 指标 | 回答的问题 |
|---|---|
| 零样本 top-1 | 目标具体属于哪一个类别，能否正确命名为 GL 或 RU |
| OOD AUC | 目标是否不属于六个已知类 |

EXP-003a 使用真值框，主要测量 CLIP 分类和 OOD 区分能力的上界；EXP-003b 使用检测器预测框，会同时受到漏检、边界框偏差和 CLIP 分类错误影响。

两者的 OOD AUC 样本口径不同：

- EXP-003a：正式测试集中的全部合法真值框；
- EXP-003b：与真值框达到指定 IoU 并成功一对一匹配的检测框。

因此 003b 的 OOD AUC 不能代表漏检目标，也不能仅凭它高于 003a 就断言端到端
系统更强；检测器可能先筛掉了困难样本。

论文中应将该指标准确表述为“预留类别 OOD AUC”。GL/RU 来自已有标注类别的人为留出，它不能代表所有未知物体、未知天气、未知摄像头或完整开放世界异常检测能力。AUC 是无固定阈值的排序指标，也不能替代实际部署时对 OOD 阈值、误报率和漏报率的选择。

### 端到端区域提议指标

EXP-003b 先忽略检测器的六类预测名称，按检测置信度将预测框与 8 类真值框做
类别无关的一对一贪心匹配。默认参数为 `conf=0.10`、NMS IoU=0.70、匹配
IoU=0.50。输出包括：

- `detection_recall`：每类真值框中有多少获得匹配区域；
- `clip_top1_on_detected`：只在匹配框上计算的 CLIP top-1；
- `end2end_zeroshot_recall`：以全部 GL/RU 真值框为分母，只有“获得匹配且
  CLIP 命名正确”才计为成功；
- `end2end_zeroshot_precision`：以所有被 CLIP 命名为 GL/RU 的检测框为分母；
  未匹配背景框或错误匹配框被命名为 GL/RU 时会计为假阳性；
- `end2end_zeroshot_f1`：端到端 precision 与 recall 的调和平均；
- `unmatched_detections_per_image`：固定阈值下每张图的多余区域提议数。

003b 会让 CLIP 处理所有检测框，而不只处理成功匹配真值的框。只有 OOD AUC
由于需要可靠的已知/OOD 真值身份，仍限定在匹配框上计算。
当前 top-1 是 8 类强制选择；尚未用 OOD 阈值拒绝低可信框。因此端到端
precision 反映“强制命名”条件下的误报，部署阶段仍需另行在验证集选择拒识阈值。

这些量依赖置信度、NMS IoU、匹配 IoU、输入尺寸和最大检测数。论文表格必须
同时注明阈值，不能把某个固定阈值结果写成与阈值无关的模型属性。003a 与
003b 的总体差距可以报告，但检测召回和分类正确率存在条件依赖，不能直接拆成
两个可加的“损失”。

### Wilson 置信区间

CLIP 脚本为 top-1、提议召回和端到端 recall 输出 95% Wilson 区间。正式测试集
只有 GL 17 框、RU 42 框，单类比例的随机波动较大，所以正文应按“正确数/总数、
比例、95% CI”一起报告。Wilson 区间把框近似视为独立试验；同图多框或同一
近重复组内样本仍可能相关，论文中应将其作为不确定性参考，而非严格的场景级
置信保证。

## 8. 论文报告建议

论文主表使用独立测试集结果，并注明：

- 数据划分方式；
- 测试集图像数和实例数；
- 输入尺寸；
- 随机种子；
- GPU 与软件环境；
- 是否使用预训练权重；
- 推理速度的 batch、硬件和统计口径。

单次随机种子可以用于开发阶段；形成最终论文结论时，建议对关键模型补充多个随机种子并报告均值与标准差。

项目中“检测相对提升 15%”“零样本 top-1 60%”“OOD AUC 0.85”和“延迟
100ms”均为推进实验的规划目标，不是江苏大学毕业、盲审或学位论文的单项合格
阈值。论文是否成立取决于问题定义、对照与消融、统计可信度、局限性说明和完整
写作，而不是任一指标是否越过预设数字。
